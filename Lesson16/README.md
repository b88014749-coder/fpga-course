# Frequency Meter

A hardware frequency meter implemented as an AXI4-Lite IP core for the PYNQ-Z1 FPGA board.

The design measures the number of rising edges of an input signal within a configurable measurement window. It exposes four 32-bit registers through an AXI4-Lite interface and is tested using a dedicated testbench.

## Features

- Configurable measurement window
- Rising-edge counting
- AXI4-Lite register interface
- Measurement completion status
- Tested with a simulation testbench
- Implemented and analyzed using Xilinx Vivado

## Register Map

The IP core exposes four 32-bit registers.

| Offset | Register | Access | Description |
|:------:|----------|:------:|-------------|
| `0x00` | `WINDOW` | R/W | Number of clock cycles in the measurement window |
| `0x04` | `CTRL` | W | Write `1` to bit 0 to start a measurement. Reads always return `0`. |
| `0x08` | `COUNT` | R | Number of rising edges detected during the last completed measurement |
| `0x0C` | `STATUS` | R | Bit 0 is `1` when the measurement is complete; otherwise, `0` |

### Measurement Sequence

1. Configure the measurement duration by writing the desired number of clock cycles to `WINDOW`.
2. Start the measurement by writing `1` to bit 0 of `CTRL`.
3. Wait until bit 0 of `STATUS` becomes `1`.
4. Read `COUNT` to retrieve the number of detected rising edges.

## Testbench

The testbench verifies the edge-counting functionality under different input periods and measurement window configurations.

| Test Case | Input Period (cycles) | Measurement Window (cycles) | Expected `COUNT` |
|:---------:|:--------------------:|:---------------------------:|:----------------:|
| 1 | 100 | 1,000 | 10 |
| 2 | 40 | 2,000 | 50 |
| 3 | 100 | 250 | 2 or 3 |

### Notes on Test Case 3

The measurement window is 2.5 times the input signal's period, so the number of rising edges detected depends on the relative phase between the input signal and the measurement window.

Since the input signal is asynchronous to the system clock, synchronization also affects the precise timing of edge detection.

Therefore, both `2` and `3` are valid results for this test case.

## Development Notes

### AXI4-Lite Interface

The initial AXI4-Lite interface, including four registers, was generated using Vivado's **Create and Package New IP** functionality.

### Debugging in Vitis

One challenge during development was viewing `printf()` output from the C application in Vitis. The output is available through the dedicated debug console.

### Clock Configuration

The design uses `S_AXI_ACLK` as its system clock.

The clock is generated by the Clock Wizard, which converts the PYNQ-Z1 board's 125 MHz input clock to **100 MHz**.
